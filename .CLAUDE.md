# Brev Data Platform - Claude Code Instructions

## Project Overview

This is an Infrastructure as Code (IaC) monorepo that provisions an NVIDIA GPU server on Brev and deploys a complete data platform stack. The project serves as a **development environment** replicating an on-premises data platform setup to experiment with workflows using the NVIDIA Enterprise AI stack.

### End Goal

Deploy a fully functional data platform on-demand via GitOps that includes:
- **Data orchestration** with Dagster pipelines
- **Versioned data lake** with LakeFS + MinIO
- **Interactive notebooks** with Marimo
- **AI/ML inference** with NVIDIA NIM LLMs
- **Synthetic data generation** with NVIDIA Safe Synthesizer

All managed through ArgoCD GitOps, with infrastructure provisioned via Terraform.

## Code Conventions

### Terraform Style

- Use modules for reusable components
- Environment-specific variables in `terraform/environments/<env>/`
- State stored remotely (configure backend)
- Use `terraform fmt` for formatting
- Validate with `terraform validate`

### Helm Chart Style

- One chart per application in `k8s/apps/<app>/`
- Values files: `values.yaml` (defaults), `values-dev.yaml` (environment overrides)
- Use subchart dependencies where appropriate
- Lint with `helm lint`

### Dagster Style

- Assets over ops where possible
- I/O managers for storage abstraction
- Schedules and sensors in dedicated modules
- Type annotations on all assets
- Group related assets with `@asset_group`

See `dagster/.CLAUDE.md` for comprehensive pipeline development guidelines.

### Secrets Management

- **NEVER** commit plaintext secrets
- All secrets encrypted with SOPS + Age
- Secret files end with `.enc.yaml` or `.enc.json`
- Decrypt only at deploy time

### File Naming

- Terraform: `snake_case.tf`
- Kubernetes/Helm: `kebab-case.yaml`
- Python/Dagster: `snake_case.py`
- Shell scripts: `kebab-case.sh`

## Important Notes

### GPU Requirements

- NVIDIA Brev instances must have GPU support enabled
- K3S requires `nvidia-container-toolkit` for GPU workloads
- NIM and Safe Synthesizer require NVIDIA GPU with sufficient VRAM

### ArgoCD GitOps Flow

1. Push changes to `main` branch
2. ArgoCD detects changes automatically
3. Applications sync based on their sync policy
4. Use `argocd app sync <app>` for manual sync

### Dagster Pipeline Deployment Workflow

**CRITICAL**: ArgoCD self-healing will revert any manual changes to the cluster. The ONLY way to deploy Dagster pipeline changes is through Git. See `docs/invariants/INVARIANTS.md` INV-D004.

**Submodule Structure**: The `dagster/` directory is a Git submodule pointing to `aerugo/brev-dagster-pipelines`. Changes require pushing to BOTH repositories.

**The deployment cycle:**

1. **Test locally** - Run `uv run pytest` and `uv run dagster dev` in `dagster/`
2. **Push submodule** - Commit and push in `dagster/` directory
   ```bash
   cd dagster && git add . && git commit -m "feat: changes" && git push && cd ..
   ```
3. **Update parent repo** - Stage the new submodule pointer
   ```bash
   git add dagster && git commit -m "Update dagster submodule" && git push
   ```
4. **Monitor build** - Check workflow in the dagster submodule repo: `cd dagster && gh run list`
5. **Force ArgoCD sync** - Delete the deployment to pull fresh image:
   ```bash
   kubectl --kubeconfig=kubeconfig.yaml delete deployment dagster-dagster-user-deployments-brev-pipelines -n dagster
   ```
6. **Validate deployment** - Check the pod has your new code
7. **Run jobs** - Use Dagster UI or GraphQL API
8. **Iterate** - If issues found, fix locally and repeat

**NEVER** push Docker images directly to the Brev instance. This will be reverted by ArgoCD and waste your time.

See `.claude/agents/production-deployment.md` for detailed workflow documentation.

### Data Flow

```
Raw Data → MinIO (raw-data bucket)
    ↓
Dagster Pipeline (transform/enrich)
    ↓
LakeFS (versioned data-products branch)
    ↓
Marimo/NIM/Safe Synthesizer (consume)
```

### LakeFS Branching Model

- `main` - Production data (protected)
- `staging` - Pre-production validation
- Feature branches for experimental pipelines
